# Sprint Acceptance and Definition of Done

## Sprint acceptance

Every sprint should define:

```text
business outcome
included scope
excluded scope
technical deliverables
test evidence
operational evidence
documentation changes
demo scenario
```

## Definition of done

A story is done when:

- code is merged,
- tests pass,
- contracts are updated,
- migrations are validated,
- logs and metrics exist,
- security impact is reviewed,
- user-visible failure states are handled,
- documentation is current.

## Demo requirement

Each sprint should end with a reproducible demonstration using committed fixtures or seeded data.

## Rule

A task that only works on one developer machine is not done.
